# Пространственные компоненты

`@zavx0z/immersive-space` (далее — Space) владеет авторским описанием объектов и проекций
в [едином Experience](../PROJECT.md#главный-закон). Все его компоненты используют
один пространственный контракт: правая система координат, X вправо, Y вперёд,
Z вверх, длины в миллиметрах.

## Трансформации

Положение задаётся одним `position={{x, y, z}}`, масштаб — одним
`scale={{x, y, z}}`. Масштаб безразмерный, по умолчанию единичный. Отрицательный
масштаб отражает объект; нулевые оси недопустимы. Положение объекта по умолчанию
нулевое. Вложенный объект задаёт трансформацию относительно своего родителя.

`rotation={{x, y, z}}` задаёт углы Эйлера в градусах с порядком XYZ, как
Blender XYZ Euler: сначала X, затем Y, затем Z относительно исходных осей.
Вместо углов программа может передать `quaternion={{x, y, z, w}}`.
Это взаимно исключающие формы одной ориентации; кватернион нормализуется.
По умолчанию ориентация единичная. Каждый вектор задаётся целиком и содержит
только конечные числа.

Эти имена и единицы обязательны для каждого компонента, который поддерживает
соответствующее пространственное свойство, включая новые компоненты.
Направленный Light принимает цель одним `target={{x, y, z}}` в миллиметрах.
Базовый `<viewpoint>` описан [в DOM](../dom/viewpoint/README.md). Камера ориентируется на цель с фиксированной осью вверх Z;
она не получает отдельную конкурирующую ориентацию или геометрический масштаб.
Её `fov` сохраняет свой оптический контракт в радианах, `near` и `far` — в мм.
Базовый `<hud>` следует камере; его [контракт находится в DOM](../dom/hud/README.md).
Geometry и Material описывают ресурсы своих объектов.

Повторный render с теми же числовыми значениями сохраняет изменения от жестов
и команд через ref, даже если автор создал новые объекты props. Изменение
значений обновляет тот же semantic Element и сохраняет его identity и детей.
Удаление ранее заданного свойства возвращает его значение по умолчанию.

## Базовый display

`<display>` — встроенный в Document пространственно-интерфейсный элемент,
который содержит обычный HTML. Он доступен без импорта TSX-компонента и
использует общий CSS, ввод и цикл кадров приложения. Его размер и плотность
определяются [контрактом физического дисплея](../dom/display/README.md).

Остальные пространственные теги и компоненты сохраняют действующий контракт.

## Базовые Space и ViewPoint

`<space>` и `<viewpoint>` создаются Document без фабрик и TSX-обёрток.
Их реализации и тесты находятся в [dom/space](../dom/space/README.md) и
[dom/viewpoint](../dom/viewpoint/README.md). Остальные пространственные
объекты пока используют действующие компоненты и регистрацию Space.

`<hud>` также является базовым элементом Document и доступен без импорта компонента.
Класс `HUDElement` экспортируется из `@zavx0z/immersive-dom/hud`.

## Пространственные рёбра

`SpatialEdges` импортируется из `@zavx0z/immersive-space/shape/edges` и размещается
непосредственно в общем Space. Каждое ребро имеет `id`, `route` и необязательный
числовой `color` в формате `0xRRGGBB`. `polyline` принимает массив XYZ, `cubic` —
четыре точки XYZ и необязательное число отрезков `segments` (по умолчанию 32).
Все координаты заданы в мм. Endpoints любых сущностей или сокетов разрешает
владелец модели до передачи маршрута; принадлежность одному или разным Display
не меняет представление связи.

Один `xr-line-segments` рисует общий batch native линиями толщиной 1px. При
изменении состава и маршрутов приложение изменяет `geometryRevision`; без
ревизии массив `edges` должен быть immutable. Перемещение ViewPoint не участвует
в аппроксимации. `hidden` исключает связь из batch, `disabled` задаёт приглушённый
цвет; `selectedId` и `selectedColor` меняют только диапазоны color buffer.
`spatialEdgeBounds` вычисляет осевой габарит, включая точные extrema cubic;
для округлённой polyline сохраняет консервативный габарит исходных вершин.
`tessellateSpatialEdge` возвращает числовую аппроксимацию XYZ.

Polyline принимает `cornerRadius` в мм (по умолчанию 0) и `cornerSegments`
(по умолчанию 4, максимум 64). Радиус задаёт максимальный срез от угловой вершины;
срез ограничен половинами длин соседних сегментов. Quadratic-перегиб остаётся
внутри треугольника среза и сохраняет XYZ и endpoints; дубликаты, прямые участки
и развороты обрабатываются без невалидных координат.

`visibleIds` принимает массив или Set адресов материализуемых рёбер. Обновление
этого набора при движении камеры меняет только batch видимых сегментов; общий
кеш числовых маршрутов сохраняется по `geometryRevision`. `hitTolerance` задаёт
радиус попадания луча в мм, отдельно от толщины линии. Browser выбирает ближайшее
пространственное попадание вместе с содержимым Display; нарисованный HUD имеет
приоритет. `onActivate(id, event)` вызывается обычным semantic click после
pointerdown/up по тому же ребру. Hover, bubbling, capture и cancellation принадлежат
общему Browser lifecycle. `readSpatialHit(event)` из основного Space API даёт
адрес и мировую точку попадания для обычных событий.

Материал SpatialEdges задаёт `distanceFade: 0`: цвет и alpha связи сохраняются
при приближении и отдалении ViewPoint. Рёбра остаются в обычном пространственном
проходе с depth-test; это свойство не превращает их в overlay.

`Grid` принимает `distanceFade` в мм и передаёт его существующему LineBasicMaterial
сетки. Значение по умолчанию 5000 сохраняет прежний вид; `distanceFade={0}`
удерживает видимость пола большого Space независимо от расстояния камеры.
Изменение только position сохраняет фабрику сетки при неизменном затухании.

## Пространственные объёмы

`SpatialVolumes`, `VolumeNode` и `BranchVolume` импортируются из
`@zavx0z/immersive-space/shape/volumes`. Объём задаётся `id`, согласованными торцами
`from` и `to` и необязательным числовым RGB либо CSS `color` семейства. Торец принимает четыре XYZ
угла или горизонтальный Layout Rect3 `{x,y,z,width,height}` в мм. Одинаковые XY
габариты дают полный прямоугольный блок; различные торцы дают сужающуюся ветвь.
Замкнутые торцы включены по умолчанию, поэтому leaf тоже сохраняет весь объём.

Один общий `SpatialVolumes` кеширует геометрию по `geometryRevision` и группирует
видимые записи по цвету семейства: один Mesh и LineSegments на группу. `visibleIds`
меняет материализуемый набор без повторного чтения торцов; ViewPoint не участвует
в этом расчёте. Компонент не создаёт Display, Canvas, Document или collision body.
Владелец Nodes компонует один существующий Display с содержимым каждой сущности.

Branded `CssStyle` через `style` задаёт настоящий CSS на пространственном Element.
Переменные наследуются от Space и других предков того же Document:
`--spatial-volume-tint` (по умолчанию белый), `--spatial-volume-opacity` (.12),
`--spatial-volume-appearance` (`holographic` либо `glass`) и
`--spatial-volume-outline-opacity` (.65). Числовой RGB умножается на tint; строковый CSS color разрешается на своей tint-группе через общий каскад;
opacity не зависит от камеры. Renderer разрешает обычный каскад и `var()`, Browser
передаёт значения в публичный `XRMaterialProjectionContext`. Изменение материала
сохраняет Mesh identity и ресурсы геометрии.

`onActivate(id, event)` может выбирать coarse поверхность до размещения HTML
Display. `disabledHitIds` исключает сущности с уже живыми Display, а
`interactive: false` отключает picking ветви. Ввод, bubbling и capture обслуживает
общий Browser SpatialHit; объём не ограничивает движение ViewPoint.
