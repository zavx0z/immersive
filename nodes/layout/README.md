# Раскладка

`@zavx0z/immersive-nodes-layout` принимает измеренный числовой граф и возвращает геометрию.
Пакет не измеряет текст, не создаёт DOM, Canvas, Renderer или NodeTree и не
управляет панорамированием. Его production-зависимости — Dagre и d3-dag.

## Алгоритмы

| Алгоритм | Вход | Результат и ограничения |
| --- | --- | --- |
| [Fixed](./algorithm/fixed/index.ts) | Измеренные ноды, `y` портов, связи, viewport, spacing | `RIGHT` / `DOWN`, источник `EAST`, приёмник `WEST`, ортогональные sections. Один порт с конфликтующими ролями отклоняется |
| [Adaptive](./algorithm/adaptive/index.ts) | Тот же граф с `capability` и `allowedSides` | Одна сторона для каждого точного сокета, включая общий. [Диагностический вариант](./algorithm/adaptive/diagnostic/index.ts) возвращает также bounded-search counters |
| [TopDown](./algorithm/top-down/index.ts) | Плоский DAG: точные `x` портов либо `attachment: "contour"` | Прежние `SOUTH` → `NORTH` или пересечения фигур, cubic curves. [Контракт и parity evidence](top-down-parity.md) |
| [Hierarchy](./algorithm/hierarchy/index.ts) | Лес карточек: `id`, `parentId`, измеренные `width`/`height` | `DOWN`, устойчивый порядок детей и корней, ортогональные линии. O(n) времени и памяти без рекурсии и viewport |
| [Compound](./algorithm/compound/index.ts) | Измеренные карточки и вложенные Frames: общий `LayoutNode` | Компактные строки внутри каждой рамки, стабильная геометрия по ID, O(n log n) времени / O(n) памяти без рекурсии. Связи независимы |
| [Prism Tree](./prism-tree/README.md), самостоятельный пакет | Измеренные Displays, `parentId`, веса и расстояние между слоями | Параллельные XY-слои по глубине, точные размеры, одинаковая глубина тел независимо от промежутка между слоями и непересекающиеся объёмы прямоугольных ветвей. O(n log n) |
| [Coffman–Graham](./algorithm/coffman-graham/index.ts) | DAG, `x` портов и `maxNodesPerLayer` | Ограниченные по ширине слои, cubic curves и массив crossings. Цикл возвращает typed witness |

У Adaptive один `source/shared` может соединяться с двумя приёмниками:
алгоритм возвращает выбранные стороны, число кандидатов и причины отказа.
Production-диапазон `maxNodesPerLayer` у Coffman–Graham — целое число от 2 до 16.
Пустой массив `crossings` означает только отсутствие пересечений на данном входе.

Hierarchy предназначен для полного дерева, где каждый узел имеет одного родителя.
Он сохраняет размеры карточек и размещает соседние поддеревья в отдельных
горизонтальных областях. Узлы одинаковой глубины начинают общий слой; высота
слоя равна максимальной высоте его карточек. Политика не уплотняет пустые места
между разновысокими ветвями. Порядок массива определяет порядок корней и детей.
Все узлы входят в результат; ширина полного леса зависит от числа и размеров
листовых ветвей, камера и zoom принадлежат потребителю.

```ts
import {layoutHierarchy} from "@zavx0z/immersive-nodes-layout/hierarchy"

const layout = layoutHierarchy({
  nodes: [
    {id: "repo", width: 220, height: 48},
    {id: "package", parentId: "repo", width: 180, height: 64},
  ],
  options: {siblingSpacing: 24, layerSpacing: 64},
})
```

`HierarchyLayoutError` возвращает `code` и `witness` для дубликатов, неизвестного
родителя, цикла и некорректных чисел. Размеры должны быть конечными положительными
числами, расстояния — конечными неотрицательными. Узлы результата сохраняют
входной порядок. Рёбра используют общий `LayoutEdgeSection` и указывают
`sourceNodeId`/`targetNodeId`; id ребра — `hierarchy:<индекс ребёнка>`.
Bounds включают все прямоугольники и маршруты.

Compound размещает соседей в компактных строках, сортируя их по измеренной высоте,
ширине и ID. Желаемое отношение ширины к высоте задаётся `aspectRatio`, по умолчанию
1.5; это ориентир упаковки, а не ограничение размера карточки. Родитель расширяется
до размеров детей, отступов `padding` и собственного `contentHeight` (по умолчанию
исходный `height`). Лист сохраняет измеренный размер. Порядок результата совпадает
с входом, перестановка входа не меняет прямоугольники по ID. Нет портов, маршрутов
и перебора вариантов по форме viewport.

```ts
import {layoutCompound} from "@zavx0z/immersive-nodes-layout/compound"
import {createRectangleIndex} from "@zavx0z/immersive-nodes-layout/rectangle-index"

const result = layoutCompound({
  nodes: [
    {id: "frame:repo", width: 1, height: 40, contentHeight: 40},
    {id: "package", parentId: "frame:repo", width: 960, height: 680},
  ],
  options: {spacing: 24, padding: 24, aspectRatio: 1.5},
})
const cards = result.nodes.filter(node => node.id === "package")
const index = createRectangleIndex(cards)
const visible = index.query({x: 0, y: 0, width: 1_600, height: 900}, {limit: 100})
```

Владелец данных заранее различает ID карточек и Frames; раскладка сохраняет оба
набора в общем `nodes`. `CompoundLayoutError` возвращает `code` и `witness` для
структурных и числовых ошибок. Глубина дерева не ограничена стеком вызовов.
Алгоритм рассчитывает переданный рабочий набор: выбор части большого каталога,
загрузка остальных частей и принятие ревизии принадлежат потребителю.

`createRectangleIndex` копирует готовые прямоугольники и собирает неизменяемый
сбалансированный BVH за O(n log n). Повторные запросы отбрасывают целые области
без просмотра всех карточек. `query` возвращает ID пересечений в стабильном
пространственном порядке и `truncated`; положительный `limit` по умолчанию 1000.
Касание границы включается, точечный запрос допустим. При сильном перекрытии областей
пространственный поиск может посетить весь индекс; лимит ограничивает выдачу.
Перемещение камеры меняет query, пересчёт геометрии создаёт новый индекс.

## Маршруты готовых карточек

`@zavx0z/immersive-nodes-layout/orthogonal` экспортирует `routeOrthogonal`. Вход
содержит готовые прямоугольники карточек и точные source/target anchors с `nodeId`,
`point` и стороной `WEST` / `EAST` / `NORTH` / `SOUTH`. Координаты общие для всего
переданного рабочего набора. Frames не передаются как obstacles; placement не меняется.
Clearance от карточек по умолчанию 12. Каждый принятый сегмент проверяется по
пространственному индексу расширенных прямоугольников; terminal stub касается
собственной карточки. Маршруты могут пересекать друг друга и использовать общий коридор.

Сначала проверяются короткие ортогональные кандидаты у краёв endpoint-карточек.
Для сложных связей строится общая сетка видимости границ всех расширенных карточек
и точных portals. Сегменты сетки проверяются лениво и кешируются между связями.
Ограниченный A* использует общие массивы и принимает только пути, повторно проверенные
по всему пространственному индексу. Изолированный поиск среди первых препятствий
не заменяет общую связность свободных коридоров между вложенными группами.

Весь batch имеет `maxEdges` (по умолчанию 4000, максимум 10000), `maxGridPoints`
(100000, максимум 1000000) и `maxSearchSteps` (1000000, максимум 8000000).
До создания массивов проверяется размер сетки; предел шагов поиска действует
на все сложные связи вместе. Превышение возвращает `GRID_BUDGET` или `SEARCH_BUDGET`,
простые безопасные связи продолжают обрабатываться. Для малых полных наборов
сохранён прежний shared solver без placement: `maxObstacles` (32, максимум 64)
ограничивает размер всего набора карточек, `maxFallbacks` (8, максимум 64) — число
его вызовов. Каждый segment query имеет предел 256 пересечений; усечённая проверка
не считается успешной.

Результат содержит `edges` с ортогональными `points`, `failures` с причиной
исчерпания budget или отказа поиска, общие `bounds` карточек и маршрутов,
`fallbackAttempts`, `gridPoints` и `searchSteps`. Порядок совпадает с входными связями, ограниченный поиск
выполняется в стабильном порядке ID. Отказ означает, что эта bounded policy не
получила безопасный путь, и не доказывает математическую невозможность маршрута.
Потребитель отображает отказ явно; рисовать прямую линию через карточки вместо
отказа нельзя. Перенос готовых points в мировые координаты и ViewPoint остаётся
у потребителя. Это числовой проход на принятой ревизии, а не работа каждого кадра.

Регрессионный [числовой снимок actual каталога](./tests/references/orthogonal-actual.json)
получен из 428 subjects опубликованного Project: 427 точных связей для viewport
1920×1088 и 3840×2176. Provenance сохраняет SHA-256 исходного каталога и правило
измерения карточек. [Проверки](./tests/orthogonal-actual.test.ts) требуют все маршруты
без отказов и независимо проверяют каждый сегмент против каждой из 428 карточек,
clearance, окончания и одинаковую геометрию при перестановке входа. Это числовое
свидетельство; визуальная приёмка опубликованного Web остаётся отдельной проверкой.

Фиксированная политика экспортирует `FixedLayoutInput` и `FixedLayoutOutput` из
`@zavx0z/immersive-nodes-layout` и `@zavx0z/immersive-nodes-layout/fixed`. Они заменили прежние alias общего
протокола `FixedLayoutGraph` и `FixedLayoutResult`; `layoutFixed` принимает
измеренный вход и возвращает ту же числовую геометрию со сторонами портов.

## Числовой протокол

[LayoutGraph / LayoutResult](./protocol/types/src/protocol.ts) задаёт measured
размеры, `parentId`, `contentHeight`, port offsets, стороны, bounds и sections
с bend points. Viewport входит в Fixed/Adaptive, но не переносится в результат.
TopDown и Coffman–Graham возвращают собственные числовые результаты; их
визуальная интеграция с NodeEditor требует отдельного договора.

## Воркеры

Каждый алгоритм имеет собственные [client/executor](./execution/worker/src/index.ts).
Worker получает graph через production client и возвращает envelope с
`requestId` и `generation`. Отказ приходит как `WorkerRemoteError` с typed
witness, когда он предусмотрен политикой. После расчёта client освобождает Worker.
Транспорт отклоняет устаревшее поколение и новые запросы после `dispose`.
