# Призматическое дерево

`@zavx0z/immersive-nodes-layout-prism-tree` — самостоятельный числовой алгоритм
внутри Layout. Его вход — конечный рабочий набор измеренных Displays и `parentId`.
Результат содержит XY-прямоугольники, слои, тела каждого узла и прямоугольные
ветви между слоями. Движок, DOM, материалы, камера, навигация, загрузка данных
и residency остаются у своих владельцев. Другие алгоритмы Layout сохраняются.

```ts
import layoutPrismTree from "@zavx0z/immersive-nodes-layout-prism-tree"
import type {ImmersiveNodesLayoutPrismTree} from "@zavx0z/immersive-nodes-layout-prism-tree"

const input: ImmersiveNodesLayoutPrismTree.Input = {
  nodes: [
    {id: "project", width: 480, height: 272},
    {id: "repo", parentId: "project", width: 480, height: 272},
    {id: "mobile", parentId: "repo", width: 98, height: 220.5},
  ],
  options: {layerGap: 240, spacing: 12, aspectRatio: 1.5, bodyDepth: 100},
}
const geometry = layoutPrismTree(input)
```

Публичное пространство содержит только роли `Input` и `Output`. Составляющие
форм принадлежат отдельным файлам `contract/`; тип прямоугольника потребитель
получает через `ImmersiveNodesLayoutPrismTree.Output["nodes"][number]["rect"]`.
Это сохраняет происхождение определения и не добавляет самостоятельные роли
в namespace, читаемый MetadataCollect.

Все размеры задаются в одной выбранной системе мировых единиц. Ширина и высота
каждого узла **в точности равны входным**, без общей нормализации и без роста
карточки до площади поддерева. Поэтому desktop/mobile aspect сохраняется
индивидуально. `weight` задаёт приоритет одинаковых по размеру областей соседей, не размер Display.
`aspectRatio` — ориентир локальной упаковки детей, а не обещание изменить aspect узла.

`rect` задаёт нижний левый угол `(x,y)`, постоянную высоту `z` плоскости XY,
`width` и `height`. Углы для loft идут в одном порядке на обоих концах:
`[x,y,z]`, `[x+width,y,z]`, `[x+width,y+height,z]`, `[x,y+height,z]`.
Слои углубляются вдоль отрицательной Z. Порядок результата `nodes` исходный;
геометрия, IDs тел и ветвей, порядок узлов слоя устойчивы к перестановке входа.

Каждый узел имеет ровно одно тело `stems`: полное сечение Display продолжается
без изменения XY на одинаковую глубину `bodyDepth`. Это относится **и к листьям**.
Только на нижнем торце тела родителя появляются отдельные `branches.from`;
ветвь прямоугольным loft соединяется с точным `rect` ребёнка следующего слоя.
Родитель не повторяется в массиве детей и не заменяется отдельной карточкой
развилки. Один родитель с одним ребёнком имеет полное departure-сечение.

Земля `floorZ=0` проходит по нижнему торцу самого неглубокого листа.
`groundDepth` — глубина этого первого окончания. При фиксированном промежутке
узел глубины `d` лежит на
`z=(groundDepth-d)*layerGap+bodyDepth`, его тело заканчивается на
`z=(groundDepth-d)*layerGap`. Лист этого уровня опирается на землю; более
глубокие ветви продолжаются в подвале. Листья не выравниваются по нижнему слою.
Пустой набор имеет нулевые bounds и `groundDepth=null`.

### Постоянный шаг и независимая глубина тела

`layerGap` одинаков для всех уровней и не зависит от ширины веера или состава
поддеревьев. `bodyDepth` одинаков для каждого тела и задаётся независимо от шага;
должно выполняться `0<bodyDepth<layerGap`. По умолчанию глубина равна половине
шага, что сохраняет прежнюю числовую геометрию. При явно заданной глубине
увеличение шага удлиняет только промежуток ветви, не тела. Ветвь занимает
`layerGap-bodyDepth` вдоль Z. Размеры XY, локальные области и IDs не меняются.

## Локальные области поддеревьев и основание непересечения

Алгоритм сначала проходит дерево снизу вверх. Каждый родитель компактно упаковывает
**полные XY-footprints дочерних поддеревьев**, а не только карточки их корней.
Упаковка использует существующий публичный `Layout/compound` и учитывает размеры
этих областей. Собственный footprint родителя — максимум его точного Display
и общего бокса упакованных детей. Длинная цепочка резервирует одну XY-область,
большое ветвление требует больше пространства. Одинаковые Display-размеры Repo
не делают области их разных поддеревьев одинаковыми.

Дети центрируются как группа в собственной области родителя. Во втором проходе
координаты передаются сверху вниз одной трансляцией от родителя. Display узла
лежит в центре своей области и сохраняет входной размер. Единственный ребёнок
имеет **тот же XY-центр**, что родитель, независимо от окончания соседних ветвей.
Потомки не выходят из виртуальной области своего поддерева; области соседних
поддеревьев не пересекаются. Это только числовые резервы пространства: дополнительных
Display, Frames или сущностей алгоритм не создаёт.

Слои группируют уже полученные координаты по глубине. Они не задают матрицу,
не переупаковывают сцены и не возвращают оставшуюся глубокую ветвь к общему центру.
Итоговая глобальная плотность отдельного слоя не является целью: сохранение
локальных семейных ветвей важнее удаления всех пустых областей.

Прямоугольники departure — одна положительная affine-проекция **полных дочерних
footprints** на неизменный нижний торец родителя. Поэтому размеры departure
выражают нужное место поддеревьев; target остаётся точным Display ребёнка.
Для единственного ребёнка departure совпадает с полным торцом родителя.

Области соседей разделены на всей глубине. Ветви разных семейств целиком лежат
в их соответствующих областях: оба endpoint-сечения находятся внутри области,
а промежуточные сечения — их convex interpolation. Внутри одной семьи departure
сохраняет ось и порядок разделения полных footprints; arrival лежит внутри тех
же footprints. Gap между сечениями двух ветвей — affine-интерполяция двух
неотрицательных endpoint gaps и не становится отрицательным внутри промежутка.
Это основание непересечения **полных объёмов**, а не только карточек. Тела занимают
первые `bodyDepth` единиц промежутка; разные глубины имеют отдельные Z-банды. Связанные тела
и ветви намеренно соприкасаются на торцах.

Проходы итеративны. Суммарный размер всех входов локальной упаковки равен O(n),
сортировки дают O(n log n) времени, память — O(n). Production не сканирует все пары.
Chain и comb не приводят к O(n²).

Большие размеры, веса или глубина, вызывающие числовое переполнение, возвращают
`PrismTreeLayoutError` с `code` и `witness`; геометрия с неконечными числами не
публикуется. Дубликаты, неизвестные родители и циклы также имеют точное свидетельство.

## Проверки

`bun run check` проверяет типы и поведение пакета. Тесты независимо проверяют
endpoint separation и exact affine intersection по общему Z-интервалу всех пар тел и ветвей,
проверяют все тела, постоянный шаг, независимую глубину, aspect, землю и подвал, frozen вход и детерминизм.
Actual fixture сохраняет исходные 428 IDs и связи опубликованного Project с
SHA-256 источника; варианты desktop и mobile требуют 428 тел и 427 ветвей.
Отдельные проверки покрывают 20000 уровней, 20000 детей, comb из 12000 узлов,
разные размеры/веса, нулевой spacing и числовые/структурные отказы.
Это числовые свидетельства; визуальная приёмка объёмов в существующем Experience
выполняется владельцем представления отдельно.
