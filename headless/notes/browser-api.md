# Headless: браузерный контракт без окна

Headless предоставляет компонентам и общему Renderer браузерные API с теми же
сигнатурами, результатами, ошибками и жизненным циклом. Компонент и сценарий
не выбирают другой способ работы для Bun: различия среды реализуются внутри
Headless. Одинаковое имя метода без одинакового поведения не считается поддержкой.

Сценарий использует `createHeadless`, `render`, `capture`/`screenshot` и `dispose`.
Создание Document, Canvas, Renderer, подключение темы и платформенных API
принадлежат Headless. Локальные заменители этих механизмов в сценариях запрещены.

## Изображения

Общий загрузчик продолжает вызывать `createImageBitmap` и
`GPUQueue.copyExternalImageToTexture`. Headless реализует эти API для нативной
среды, включая пиксели, размеры, альфа-канал и освобождение ImageBitmap.
Нативный `writeTexture` допустим внутри реализации метода GPUQueue.
Подмена методов в компонентах и ветки `if (headless)` в загрузчике не нужны.

`render` и снимок ожидают ресурсы кадра. Ошибка декодирования отклоняет операцию;
прозрачная заглушка не означает успешного рендера. Глобальные API устанавливаются
на время операции host и восстанавливаются при завершении, в том числе ошибочном.

## Штатные средства и проверенные ограничения

Сначала используются возможности Bun, затем уже установленные нативные библиотеки.
Bun 1.4.2 умеет декодировать и перекодировать растровые форматы, но `.bytes()`
возвращает закодированный файл; публичного вывода RGBA нет. SVG отклоняется с
`ERR_IMAGE_UNKNOWN_FORMAT`. `Bun.Image` используется для PNG-снимков.

В `bun-webgpu@0.1.7` метод `copyExternalImageToTexture` объявлен, но не реализован.
Это пробел среды выполнения, который устраняется внутри Headless, сохраняя
публичный контракт WebGPU. Нативное декодирование не запускает браузер или CLI.

## Граница готовности

Требование распространяется на браузерное поведение, необходимое общему
конвейеру и компонентам. Наличие DOM и WebGPU само по себе не доказывает полную
совместимость с браузером. Каждая реализованная возможность подтверждается
проверками поведения и пикселей. Неподдержанная возможность остаётся явным
пробелом; её нельзя молча игнорировать или объявлять успешно выполненной.

## Текущий срез реализации

Реализованы Blob (включая SVG) и ImageBitmap как источники, независимое владение
пикселями, `close`, crop с прозрачной областью за границами, resize и flipY.
Копирование в RGBA8/BGRA8-текстуры поддерживает origin, flipY и преобразование
предумноженного альфа-канала. Размеры и пиксели проверяются отдельными тестами.

Нативное декодирование использует GdkPixbuf и его librsvg-loader через Bun FFI.
На этом Mac они уже установлены MacPorts; дополнительные npm-зависимости,
браузерные процессы и CLI не требуются. Кодек загружается при первом изображении.

Это ещё не полная реализация браузера. Источники Canvas, VideoFrame,
HTMLImageElement и ImageData, цветовые профили вне sRGB, Canvas 2D, анимация
и остальные форматы назначения WebGPU требуют отдельных проверенных реализаций.
Для явно неподдержанных типов источников и форматов назначения API сообщает
`NotSupportedError`. Совпадение всех правил WebIDL и GPU validation с браузером
ещё не подтверждено; текущие тесты доказывают перечисленные случаи.
