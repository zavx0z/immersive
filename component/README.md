# Компоненты

`@zavx0z/immersive-component` управляет состоянием и жизненным циклом скомпилированных
компонентов в одном семантическом Document. Пакет связывает результат компиляции
Template с существующими DOM-элементами и обновляет их при изменении состояния.

## Ответственность

- Монтирование, обновление и размонтирование компонентов в переданном контейнере.
- Hooks для состояния, эффектов, refs, context и подписок на внешние stores.
- Композиция дочерних элементов, ключи и сохранение идентичности при обновлениях.
- Передача скомпилированных стилей и привязок существующему документу.
- Очистка эффектов, подписок и refs при завершении жизни компонента.

Browser создаёт приложение и владеет Canvas, вводом и кадрами. Component
обслуживает компоненты внутри этого приложения; CSS-раскладка и GPU-отрисовка
принадлежат Renderer и WebGPU.

## Композиция без JSX

`root.render(template, props, {content})` и свойство `componentElement.content`
используют один `slotContents` ABI. Ключ содержимого — действующее имя outlet;
пустая строка обозначает безымянную область. Значения принимают настоящие Nodes,
DocumentFragment, prepared component values, текст и их фиксированные группы.

Закон: узлы принадлежат Document получателя, не копируются и сохраняют identity,
значения полей и собственные listeners при обновлении props и same-Document
переносе host. Component использует общий планировщик документа. Отключение
custom element освобождает hooks и привязки; повторное подключение использует
ранее принятое содержимое и создаёт новый lifecycle компонента.

Fragment раскрывается в момент назначения содержимого. Его снимок принадлежит
конкретному root либо custom element. Повторный props update с тем же readonly
content map сохраняет принятые Nodes; новое назначение уже пустого Fragment
другому получателю остаётся пустым. Один Node нельзя назначить двум слотам
одновременно. После явного переноса Node прежний диапазон не удаляет его при cleanup.

`html/compile` принимает те же prepared values и Nodes в child interpolation.
Регистрация custom element позволяет использовать `.props` и `.content`
property bindings в HTML. Это собственный нижний контракт компонента;
native Shadow DOM slots здесь не заявляются.

При первом успешном подключении custom element однократно принимает исходные
`childNodes`: атрибут `slot` выбирает точное имя области, а его отсутствие —
безымянную. Поэтому `parseFragment` и `innerHTML` сохраняют исходные HTML-узлы
в готовом компоненте. Если заданы `initialContent` или явное `.content`,
одновременные исходные дети отклоняются вместо неявного объединения двух входов.
После первого подключения изменения задаются через `.props` и `.content`;
автоматического наблюдения за каждым последующим append нет. Узлы имеют
обычные фактические DOM-предки; shadow tree не создаётся.

Getters отражают принятый ввод. Неуспешный render сохраняет предыдущие props и
content; после ошибки первоначального подключения исправленный setter повторяет
монтирование в том же Document. HTML lifecycle выполняется после публикации
готового диапазона в переданном host, а cleanup освобождает все соседние значения
даже при ошибке одного callback.

## Публичный API

Основной вход — `@zavx0z/immersive-component`: `createRoot`, hooks, `createContext`,
`component`, `memo` и средства композиции. Для запуска приложения используется
Browser `createRoot(canvas)`, который составляет этот механизм с остальной
платформой.

Поддерживаемое поведение React-подобного API описано в публичных exports
`@zavx0z/immersive-component/compatibility` и `@zavx0z/immersive-component/compatibility.json`.
Сходство названий hooks само по себе не означает полной совместимости с React.

## Документация и проверки

Контракты находятся в TSDoc исходников, начиная с `src/index.ts`.
[Заметка о переносе между слотами](meta/notes/slot-transfer.md) сохраняет отложенную
работу над сохранением экземпляра при смене области композиции.
Проверки состояния, документа и host-привязок находятся в `tests`.
Команда `bun run check` из директории пакета проверяет типы и выполняет тесты.

Состав пакетов определяет `package.json#workspaces` репозитория; этот README
остаётся обзором принадлежащего пакету контракта.
