# Immersive

Immersive — единая визуальная платформа для приложений с пространственной сценой,
экранами и интерфейсом. Императивный DOM, декларативная разметка и готовые
компоненты используют один документ, раскладку, ввод и отрисовку WebGPU.

## Публичная поставка

Приложения подключают корневой пакет `@zavx0z/immersive`:

| Вход | Ответственность |
| --- | --- |
| `@zavx0z/immersive` | DOM, пространственные элементы и `createRoot(canvas)` без компонентного runtime |
| `@zavx0z/immersive/XReact` | Состояние, эффекты, композиция и монтирование готовых компонентов в этот DOM |
| `@zavx0z/immersive/XReact/browser` | JSX-корень Canvas поверх того же подключения документа |
| `@zavx0z/immersive/ui` | Готовые универсальные компоненты интерфейса |
| `@zavx0z/immersive/space` | Пространственные компоненты и преобразование semantic-сцены |
| `@zavx0z/immersive/compiler` | Подключение JSX-компилятора к Bun при сборке приложения |

Точный состав входов, включая Engine, Renderer, Nodes, Markdown и инструменты,
задаёт `package.json#exports`. Исходные workspace-пакеты сохраняют своих владельцев;
корневые входы не создают вторую реализацию их функциональности.

`bun run build` выпускает ESM с общими chunks и самостоятельным графом `.d.ts`.
Обычный импорт получает готовый JS; условие `source` служит разработке владельца.
Потребитель компилирует свой JSX с `jsxImportSource: "@zavx0z/immersive/XReact"`,
не включая исходники Immersive в `sourceRoots`. Компилятор читает типы готовых
компонентов, включая props и слоты. Исполнение не требует компилятора, MetaFor
или среды Storybook. Проверка готовой поставки: `bun run test:distribution`.

`browser.json` перечисляет публичные ESM-входы, файлы и их контрольные суммы.
Потребитель может связать и доставить эти файлы без повторной компиляции.
Происхождение source-входов предназначено для проверки самих компонентов Immersive:
они подключают тот же подготовленный DOM и планировщик. Обновление приложения
само по себе не запускает сборку платформы.

Готовый компонент можно загрузить через `import()`, передать в `XReact.createRoot`
или зарегистрировать через `componentElement` и `document.customElementRegistry`.
Регистрация добавляет DOM-host только там, где приложению нужен самостоятельный
элемент; внутренняя JSX-композиция сохраняет прямое монтирование. Оба пути
используют один компонентный планировщик документа. Контракт lifecycle и
пространственных hosts описан у DOM и Browser; это не заявление полной
реализации всех браузерных DOM API.

DOM-содержимое передаётся в действующие слоты без JSX и без копирования узлов:

```ts
import {createDocument} from "@zavx0z/immersive"
import {createRoot} from "@zavx0z/immersive/XReact"

const {Pane} = await import("@zavx0z/immersive/ui")
const document = createDocument()
const host = document.createElement("main")
document.append(host)
const content = document.createElement("p")
content.textContent = "Обычный DOM внутри готового компонента"
const root = createRoot(host)
root.render(Pane, {variant: "outlined"}, {content: {"": content}})
```

Пустое имя обозначает безымянный слот. Для Custom Element тот же вход доступен
как `.content`; при первом подключении он может принять исходных DOM-детей
по их атрибуту `slot`. Это композиция в одном настоящем дереве; Shadow DOM
и отдельное распределяемое дерево не создаются. `innerHTML` и `parseFragment`
принадлежат DOM, а HTML-шаблоны и JSX используют общий механизм DOM-привязок.

## Устройство платформы

Одно приложение использует один semantic Document, один Canvas, одно Space,
один ViewPoint и общий цикл ввода и кадров. Display и HUD показывают содержимое
того же документа. Обновления сохраняют существующие элементы и состояние
компонентов.

- **DOM** хранит дерево документа, атрибуты, события, фокус и состояние элементов.
- **JSX** компилирует TSX/CSS; **Template** задаёт готовый формат,
  а **Component** исполняет его, управляя состоянием и эффектами.
- **Renderer** вычисляет стили, раскладку и данные для рисования и выбора цели ввода.
- **Engine и WebGPU** обеспечивают объекты сцены и выполнение отрисовки.
- **Space и Browser** связывают пространственные элементы с приложением,
  Canvas, вводом и кадрами.
- **UI** предоставляет общие компоненты интерфейса.
- **NodeTree, Layout и Nodes** отвечают за модель графа, его раскладку и редактор.
- **DevTools** предоставляет диагностику существующего документа и его проекций.

Состав самостоятельных пакетов задан в `package.json#workspaces`.
Границы пакетов определяют ответственность; подробные контракты находятся
у соответствующих реализаций.
