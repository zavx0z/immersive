# Задачи по большим документам

* [ ] Реализовать отображение видимых строк с небольшим запасом, сохранив полный
  документ, выделение, копирование, поиск, курсор и прокрутку.

CodeEditor создаёт все строки и токены. `showLineNumbers=false` скрывает номера,
но не удаляет их элементы. В закрытом общем журнале Storybook до исправления App
оставалось 71 094 из 72 374 semantic элементов; ответ около 494 365 символов,
13 121 строк. Native DOM при этом имел только 64 узла: речь о semantic Document.
Это не основание обрезать текст, разбивать ответ на страницы или создавать
второе дерево/Canvas. Проверить существующие возможности layout/scroll;
недостающий общий механизм передать владельцу платформы.

[Компонент](../index.tsx).
[Потребитель в App](../../../../../../storybook/app/web/page/shell/mcp-window/src/request-list.tsx) уже
передаёт пустой текст неактивному редактору и восстанавливает полный ответ при
открытии; identity внешнего редактора сохраняется. Это решило скрытые строки,
но большой открытый документ всё ещё создаёт весь объём.

Доказательства: [before-retained.json](research/2026-10-04/before-retained.json), [retained.json](research/2026-10-04/retained.json),
[after.json](research/2026-10-04/after.json). После правки всего 1327 элементов, в скрытом журнале 47.
[live.json](research/2026-10-04/live.json) и [after-live.json](research/2026-10-04/after-live.json) — инспекция примерно
2820 → 48,6 мс. Пять секунд наблюдения закрытого журнала не показали запросов:
проблема была в удержании дерева, активный polling не подтверждён.

Готовность: документ на 13 тысяч строк не создаёт все элементы сразу;
выделение через границу viewport, копирование полного текста, поиск,
переносы/softBreaks, редактирование и восстановление scroll работают.
Измерить память и время кадра при открытии и прокрутке. Обычные маленькие
редакторы и интерактивность сохраняются.
