# Задачи по большим документам

* [ ] Реализовать отображение видимых строк с небольшим запасом, сохранив полный
  документ, выделение, копирование, поиск, курсор и прокрутку.

До readonly окна CodeEditor создавал все строки и токены. `showLineNumbers=false`
скрывал номера, но не удалял их элементы. В закрытом общем журнале Storybook до исправления App
оставалось 71 094 из 72 374 semantic элементов; ответ около 494 365 символов,
13 121 строк. Native DOM при этом имел только 64 узла: речь о semantic Document.
Это не основание обрезать текст, разбивать ответ на страницы или создавать
второе дерево/Canvas. Проверить существующие возможности layout/scroll;
недостающий общий механизм передать владельцу платформы.

[Компонент](../index.tsx).
[Потребитель в App](../../../../../../storybook/app/web/page/shell/mcp-window/src/request-list.tsx) уже
передаёт пустой текст неактивному редактору и восстанавливает полный ответ при
открытии; identity внешнего редактора сохраняется. Это решило скрытые строки,
но большой открытый документ на момент этих измерений ещё создавал весь объём.

Доказательства: [before-retained.json](research/2026-10-04/before-retained.json), [retained.json](research/2026-10-04/retained.json),
[after.json](research/2026-10-04/after.json). После правки всего 1327 элементов, в скрытом журнале 47.
[live.json](research/2026-10-04/live.json) и [after-live.json](research/2026-10-04/after-live.json) — инспекция примерно
2820 → 48,6 мс. Пять секунд наблюдения закрытого журнала не показали запросов:
проблема была в удержании дерева, активный polling не подтверждён.

Готовность: документ на 13 тысяч строк не создаёт все элементы сразу;
выделение через границу viewport, копирование полного текста, поиск,
переносы/softBreaks, редактирование и восстановление scroll работают.
Измерить память и время кадра при открытии и прокрутке. Обычные маленькие
редакторы и интерактивность сохраняются.

## Readonly окно и точный source — 5 октября 2026

Реализовано для readonly документов больше 200 visual rows. Компонент получает
высоту строки и собственного viewport через публичную DOM layout geometry;
материализует видимые строки с запасом восемь строк с каждой стороны. Номера
следуют тому же окну; при `showLineNumbers=false` gutter вообще не создаётся.
CSS spacers сохраняют высоту промежутков, скрытые DOM Text внутри того же `code`
сохраняют весь исходник. DOM source-text регистрация освобождается при смене
режима и unmount; Renderer читает этот исходник при обычном Browser copy.
Отдельного дерева и readonly clipboard override нет.

Закреплены endpoints текущего выделения, нативный pointer anchor и реально
измеренная самая широкая посещённая строка. Между render/commit сохраняются
UTF-16 границы, включая внешний endpoint сквозного диапазона. Замена исходника
отображает смещения по неизменным краям; shrink ограничивает старое окно до
нового числа строк до обновления геометрии. `scrollToLine` открывает удалённую
строку по измеренной высоте. Resize выполняется через авторский CSS.

Проверено одним CPU прогоном: 33 tests, 322 assertions, включая девять compiled
CodeEditor/DOM/Renderer/Browser clipboard сценариев, существующие проверки
редактирования/IME/каретки, два сценария прокрутки и пять pure window plans.
Документ на 13 121 строку с CRLF, surrogate pairs и последней пустой строкой
сохраняет exact source, меньше 60 материализованных строк, меньше 300 элементов
и меньше 250 display items; проверены копирование всего текста, настоящий
Renderer drag через смену окна и Shift-drag из скрытого gap anchor, сквозной
backward диапазон, программные gap
endpoints, resize, shrink до 300 строк и editable→readonly. Owner typecheck
проходит. Checks: `test/windowing.test.ts`, `test/window-plan.test.ts`,
`../../../tests/code-editor-interaction.test.ts`,
`../../../tests/code-editor-scroll.test.ts`.

Ограничения: window учитывает собственную ограниченную высоту CodeEditor.
`height:auto` без `max-height` означает действительно большой viewport и не
даёт сокращения строк; consumer должен задать viewport своим CSS. Глобальная
горизонтальная ширина до посещения всех строк не вычисляется по приближённым
font metrics. После посещения длинной строки её измеренный extent и horizontal
scroll сохраняются при возврате. Editable большие документы сохраняют прежний
полный вывод. Реальные GPU frame time, память и визуальная Desktop-приёмка этой
проверкой не измерены; общий пункт выше до их выполнения не закрыт.

## Живая проверка readonly — 5 октября 2026

[Проверка через CDP в Storybook](../../../../../../storybook/chat/view/meta/research/2026-10-05/readonly-summary.md)
подтвердила 33–34 materialized rows при 13 010 visual rows полного JSON результата,
переход к концу и назад, горизонтальную прокрутку, закрытие и повторное открытие.
Полный текст содержит 548 153 символа; история и исходник не обрезаются.
Снимок конца просмотрен; diagnostics и consoleErrors пусты. У readonly просмотров
чата, журнала и Markdown теперь ограничен CSS viewport. Верхний общий пункт
остаётся открытым для отдельной виртуализации больших редактируемых документов;
readonly часть и её живая проверка завершены. Замеры не объявляют универсального
потолка памяти и не заменяют приёмку Владимиром.
