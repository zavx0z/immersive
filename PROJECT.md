# @zavx0z/immersive

## Цель

Одна визуальная платформа без потери действующего поведения Engine, Renderer,
UI и Node.

Главный инженерный приоритет — производительность и простой компонентный API.
Платформа владеет служебной регистрацией, синхронизацией и ресурсами; повторные
обновления сохраняют существующие объекты и обрабатывают изменившиеся данные.

## Главный закон

Одно подключённое приложение владеет одним `Document`, Canvas, `Space`, `ViewPoint`, вводом
и циклом кадров.

Координатный контракт един для всей платформы: правая система, +X вправо,
+Y вперёд, +Z вверх; одна единица сцены равна одному миллиметру. Position,
размеры Geometry, расстояния HUD и near/far камеры задаются в мм. CSS layout
задаётся в CSS px. [Общий контракт пространственных компонентов](space/README.md)
задаёт объектные position, rotation, quaternion, scale и target, а также
физический размер и плотность базового display. Quaternion и scale безразмерны. Ось вверх всегда Z и не является
параметром камеры, snapshot или приложения. Orbit сохраняет горизонт и ограничивает
наклон у полюсов. glTF приводится к этой системе преобразованием импортированного
объекта; система координат сцены при импорте не меняется.

```text
Document
└── html
    └── body
        ├── link (ресурсы приложения)
        └── Space
            ├── ViewPoint
            ├── Object
            │   ├── Asset
            │   ├── Group
            │   ├── Mesh
            │   │   ├── Geometry
            │   │   └── Material
            │   ├── Line и LineSegments
            │   ├── Text
            │   ├── Light
            │   └── Animation
            ├── Display
            │   └── UI и Node-содержимое
            └── HUD
                └── Интерфейс приложения
```

Engine и WebGPU хранят только производное представление элементов `Document`,
а не второй главный граф.
Владельцем проекции является сам Element: Display и HUD не требуют `id`.
Обычный DOM `id` остаётся авторским атрибутом для CSS и поиска. Его отсутствие,
изменение или совпадение с другим элементом не заменяет Renderer и не нарушает
ввод. Регистрация, захват указателя, подсказки и native input используют ссылки
на владельцев. Перенос сфокусированного UI между проекциями того же Document
сохраняет фокус и обновляет владельца ввода по фактическому родителю.
Обычное содержимое отображается в `Display`, весь интерфейс приложения — в
`HUD`, а трёхмерное содержимое добавляется непосредственно в единственный `Space`.

Ввод выбирает содержимое под указателем в общем пространстве. Пустые области
HUD и Display, включая layout-контейнеры и середину прозрачной рамки, не
перекрывают другие проекции. Нарисованные панели, текст, изображения, контролы
и области прокрутки сохраняют перекрытие; конец прокрутки не передаёт колесо
скрытой проекции или камере. Среди Display выбирается ближайший с содержимым
в точке попадания. Hover, нажатие, колесо, contextmenu и dblclick используют
один выбор получателя. Захват указателя сохраняет проекцию до up/cancel;
semantic capture и bubbling остаются у того же Document.

## Авторство и подключение приложения

Основой приложения является DOM, независимо от способа авторства. Императивный
код и декларативное содержимое создают и изменяют одни и те же элементы.
Подключение документа к Canvas, ввод, проекции и общий цикл кадров не требуют
JSX или компонентного runtime. Компонентное авторство использует это же
подключение; оно добавляет состояние, композицию и эффекты, сохраняя единственный
Document и единственную реализацию его отображения.

Авторская композиция передаёт содержимое между JSX-тегами и размещает его через
[слоты JSX](jsx/slot/index.ts), без поля `children` в props компонента.
Для проверок наличия содержимого используется
[hasSlot](component/slot-presence/index.ts) в текущем render.
Поля `children` в данных деревьев и служебном JSX-транспорте сохраняют своё назначение.

Публичный запуск Browser следует привычной семантике React:
`const root = createRoot(canvas)` и `root.render(<App />)`. Повторный render
обновляет существующий component root, сохраняя состояние и identity по
template/key; render(null) очищает содержимое, unmount завершает lifecycle.
Автору и агенту не нужно изучать отдельный способ монтирования. Это контракт
авторского API, а не зависимость от npm React или заявление полной поддержки
всех React features.

Template компилирует JSX аргумента render в ComponentValue. Browser создаёт один
semantic Document с html/body; Component монтирует App в этот body. Fragment
может объявлять соседние stylesheet links и единственный Space. Space содержит
ViewPoint, Display, HUD и объекты сцены. Browser не создаёт скрытые Space/камеру.
Space.frameloop задаёт общий режим demand/always и изменяется без пересоздания
приложения; pixelRatio относится к native Canvas и остаётся в createRoot options.

`ref` принимает callback или объект `useRef`: ссылка указывает на тот же
смонтированный Element и очищается при unmount. Изменение пространственного prop
применяется при изменении его авторского значения. Прямое движение от жестов или
через ref сохраняется при повторном render с прежними props; это правило не
меняет controlled-поведение обычных HTML-полей.

ViewPoint владеет сохранением и возвратом обзора: `saveState`, `dollyTo`, `reset`
изменяют ту же камеру через общий Document. Приложение хранит свой режим обзора,
а Browser обслуживает единый ввод и demand frame loop.

В авторском TSX свободное имя `document` имеет стандартный тип из `lib.dom`.
Это общий обязательный контракт авторских JSX/TSX: `Element`, `HTMLElement`,
`Document`, события и refs используют стандартные глобальные браузерные типы.
Нестандартные возможности добавляются централизованным расширением этих типов
в platform owner. Нельзя импортировать типы реализации DOM из `@zavx0z/immersive-dom`
для обычных component props/refs/events или стыковать их через `as unknown`/
`as any`. Реализация нашего DOM работает в runtime, но её типы остаются на
платформенных, внутренних интеграционных и тестовых границах. Импорт публичных
geometry helpers, доменные типы `NodeRect`/`NodeShape` и platform-owned объявления
нестандартных тегов разрешены. Отсутствующий метод исправляется в авторском
фасаде владельца платформы, а не приведением типов в компоненте.
Template связывает свободное имя `document` внутри компонента или пользовательского hook с Document
текущего ComponentRoot. Обработчики, эффекты и async callbacks захватывают эту
ссылку; другой root не может изменить их документ. Локальные параметры и
переменные `document` сохраняют своё обычное значение.
Native `window.document` и код подключения страницы не подменяются.
Это привязка имени при сборке, а не отдельное глобальное хранилище и не
объявление поддержки всех браузерных DOM API. Внутренний `useDocument` остаётся
механизмом Component для сгенерированного кода; автору он не требуется.

`createRoot` резервирует native Canvas/page, а render запускает подготовку
ресурсов и общего кадра без Promise в авторском API. Диагностика
`@zavx0z/immersive-browser/diagnostics` наблюдает готовность через inspectRoot(root).whenReady().
Это технический рубеж отрисовки, не подтверждение визуальной корректности.
Unmount отменяет подготовку и освобождает компоненты, links, ввод и кадры;
завершившаяся позже асинхронная операция не восстанавливает приложение.

Root предоставляет render и unmount. Внешние инструменты получают существующие
проекции, общий ввод и кадры через диагностику. Специальный browser/integration
принимает готовые шрифты и заимствованные native links и использует тот же
createRoot/render lifecycle; эти ресурсы не входят в обычные RootOptions.
Browser составляет Component, DOM, Renderer, Space и WebGPU через публичные контракты.

### Выделение и общий буфер обмена

App объявляет стили обычными `<link rel="stylesheet" href="…" />` рядом со Space.
Явные links полностью задают author stylesheets в порядке дерева. Только при их
отсутствии Browser подключает отдельный `./theme.css` приложения. Сборка выбирает
его исходник; стандартная тема остаётся публичным `@zavx0z/immersive-ui-component/theme/theme.css`.
Browser создаёт настоящие native links, читает загруженный CSSOM и освобождает
свои links при удалении декларации или unmount. Смена href и порядка деклараций
сохраняет identity остальных links и смонтированного приложения.

Один Document владеет стандартным Selection с одним Range. Range хранит
semantic Node и UTF-16 offset, не пиксели и не токены. Изменения дерева
сохраняют живые границы по договору DOM. Поля input/textarea сохраняют
свой отдельный value-based selection.

Renderer владеет исходными текстовыми смещениями, позицией указателя,
переносами, user-select и геометрией диапазонов. WebGPU рисует производные
подсветки и каретки в существующей проекции. Selection-only изменения
не требуют токенизации, повторного TSX render или полного layout.

Browser Root владеет одним clipboard controller, общей клавиатурой,
нативными copy/paste/cut и IME proxy. Меню и клавиатура вызывают те же
команды. UI владеет Menu/MenuItem/ClipboardMenu; корень Experience монтирует
ClipboardMenu один раз в общем HUD и передаёт существующий controller.
UI не импортирует Browser и не обращается к системному clipboard самостоятельно.
Открытие меню сохраняет цель команды; асинхронная вставка не применяется
к изменившейся или отключённой цели.

Мультикурсор принадлежит общей headless модели CodeEditor: несколько
направленных диапазонов, основной диапазон, атомарные текстовые изменения,
IME и история. Дополнительные диапазоны используют общий DOM highlight
transport, но не меняют стандартный Selection API. Interpreter владеет
только связью с файлами, Git, debugger и жизненным циклом процессов.

Договоры: [DOM](dom/selection.md), [Renderer](renderer/html/text-selection.md),
[Browser](browser/clipboard.md), [редакторская модель](tech/text-editor/README.md).

## Пакеты

Пакеты используют Bun 1.4 и TypeScript 7. Самостоятельные владельцы могут
составлять вложенное workspace: нодовая подсистема находится в `nodes`, её
дочерние пакеты сохраняют собственные package.json, зависимости и lifecycle.

Число пакетов не фиксировано. Отдельный пакет появляется, когда у него есть
самостоятельная ответственность и реальный потребитель. Текущий согласованный
состав ниже проверяется вместе с зависимостями;
новый пакет добавляется в эти проверки, а не запрещается ради числа 12.

Для сборки, тестов, файлов и процессов используется нативный Bun API, если он
покрывает задачу. Браузерный производственный код использует стандартные Web
API и не зависит от Bun. `tsc` используется только для проверки типов.

### Долгосрочная цель сборки TSX

Максимально возможные вычисления переносятся из времени работы в сборку TSX. Автор
компонента описывает один TSX и настоящий CSS; компилятор JSX заранее
создаёт DOM-план, таблицу постоянных стилей и числовую программу размеров.
Зависящие от свойств части компилируются в ограниченные привязки и пересчитываются
только при изменении своих входов. Во время работы остаются только состояние,
события и проекция уже готового плана, но не повторный разбор TSX/CSS и не
измерение DOM.

Новый нестандартный Field должен автоматически получать числовой план из своей
скомпилированной TSX-реализации. Ручная парная реализация `Component + Layout`,
центральный список видов Field и новая ветка в Nodes не являются конечным
механизмом расширения. Пока такого формата результата компиляции нет, это общий
пробел владельца `@zavx0z/immersive-template`, а не основание добавлять обход в UI или
Nodes.

компиляции публичных TSX и проекции всех готовых параметров сохраняют
наблюдаемое поведение.

## Модули пакета

Реализация группируется по ответственности. В структурном каталоге пакет
определяется собственным package.json, модуль — собственной директорией `src`,
а промежуточные директории образуют категории. `exports` задаёт публичные
импорты и не определяет роль директории; переэкспорт из `index.ts` также не
превращает категорию в модуль.

`index.ts` категории или предмета содержит ведущий `@packageDocumentation`
с описанием ответственности. Реализация предмета находится в его `src`,
локальные behavioral tests — в `tests` рядом с ним. Интеграционные проверки
нескольких предметов принадлежат `tests` пакета.

Общая и базовая механика находится в package-level `shared`, который не
появляется в структурном каталоге. Он не создаёт дополнительный runtime owner.
Импорты чужого private `src/**` и совместимые копии реализаций запрещены.
Этот договор не требует переносить несвязанные платформенные пакеты вместе
с изменением нодовой подсистемы.

### UI

UI — область универсальных элементов управления, поверхностей, представлений и
составных виджетов. Корневой `@zavx0z/immersive-ui-component` и вложенные области собирают именованный
API своих владельцев. Реализации доступны из самостоятельных пакетов;
публичные подпути UI ведут непосредственно к их физическим входам.

```text
ui/
├── index.ts
├── button/              # Button, IconButton, ToggleButtonGroup
├── field/               # Поля, числовые договоры размеров и обработка значений
├── menu/                # Menu, MenuItem, ClipboardMenu
├── navigation/           # Breadcrumbs
├── surface/             # Pane, Panel, Frame, Window, Tab и общие части поверхности
├── view/                # List, Table, Timeline, CodeEditor
├── widget/              # Inspector, Editor, Terminal, Tree и общая шапка
├── theme/               # SVG-значки, синтаксическая тема и CSS-ресурсы
├── selection/            # Проверка и выбор вариантов
├── code-editor-model/    # Текст, выделения, IME и история
├── terminal-model/       # Поток терминального вывода
├── badge/
├── divider/
├── typography/
└── tests/                # Проверки взаимодействия владельцев UI
```

Компонент владеет реализацией в `index.ts`/`index.tsx`, публичными контрактами,
сценарием использования и частными помощниками в своей `src`. Его основной
экспорт — default; контрактные типы именованы. Домены назначают публичные имена
реализациям, сохраняя владельцев. Общие расчёты, модели и ресурсы используются
через публичные входы своих пакетов. Состав всех пакетов объявляет только Repo.
Нормы размещения принадлежат [Archetypes](../storybook/package/src/architecture.md).

`FieldGroup` принадлежит `field`, `ToggleButtonGroup` — `button`, а
`Breadcrumbs` — `navigation`. Модели редактирования и терминального вывода
сохраняют отдельные входы от их визуальных представлений.

Самостоятельный Markdown принадлежит `@zavx0z/immersive-markdown`; общий parser
использует markdown-it и parse5, а отображение кода — существующий CodeEditor.
Потребители используют публичный компонент и отдельно компонуют свои действия.
Поддерживаемый синтаксис и ограничения описаны в [Markdown](markdown/README.md).

Числовые договоры Field находятся в пакетах `layout` соответствующих полей.
Они используют единые метрики из `theme/field-metrics.json`; `theme.css`
объявляет тот же набор `--field-*`. Сохранность чисел, составные размеры и
совпадение CSS с метриками проверяются совместно. Сгенерированный Template-план
остаётся целью платформы; UI не вводит отдельный механизм регистрации новых Field.

Указатели раскрытия и другие служебные знаки используют SVG либо векторные Path.
Ресурсы находятся у собственных владельцев в `theme/icon`; семейство темы
раскрывает их именованный API и сохраняет CSS как ресурс.

UI работает в предоставленном Document и не создаёт Browser Root, Canvas,
Renderer или Space. Отдельный порт буфера обмена передаётся `ClipboardMenu`
вызывающим приложением. Авторские refs и события следуют общему контракту DOM.

Каждый пакет имеет собственные package.json и README. Категории Parameter
содержат предметы с отдельными `src` и TSDoc, а общая проекция Store остаётся
в `parameter/shared`. Client и executor конкретной политики лежат рядом с
алгоритмом в `layout/algorithm/<policy>/src/worker`; транспорт поколений общий.
Пакет `node` предоставляет конкретные DiagramNode, ParameterNode и ContentNode.
ParameterNode использует Pane и готовые Parameters; ContentNode составляет его
с независимой областью содержимого. Универсальной визуальной Node нет.

Путь `nodes` выражает принадлежность подсистеме и не переносит состояние
между пакетами: `tree` владеет моделью, `layout` — числовой геометрией,
`parameters` и `sockets` — готовыми компонентами, `node` — конкретными нодами,
`@zavx0z/immersive-nodes` — отображением и взаимодействием всего графа.
У NodeTree и NodeEditor сохраняется одна принятая пара snapshot/layout;
pending блокирует старый ввод с сохранением Element и Parameter Store identity.
NodeType остаётся отдельным проектом договора, без новой материализации типов.

Геометрия конкретных нод строится из чисел до Layout. Для развёрнутой ParameterNode:
минимальная ширина `100px`, граница `1px`, шапка `22px`, верхний и нижний
отступы тела `8px` и `6px`, строка `22px`, промежуток `3px`. Поэтому пустая
ParameterNode имеет высоту `38px`, а для одинаковых строк высота равна `35 + 25n` и
центры Socket идут `42 + 25i`. Многорядный Parameter сообщает плану свою
числовую высоту от своего публичного UI-владельца; Layout и TSX используют один
и тот же выбор представления и один план. Скрытие параметров оставляет сокеты
в компактной шапке. ContentNode независимо добавляет квадрат со стороной в ширину
ноды; все четыре состояния передаются в тот же расчёт геометрии. DiagramNode
имеет собственную высоту, а круг — высоту, равную ширине.

### Space

Публичные компоненты группируются по смысловым разделам, как в
[каталоге Drei](https://drei.docs.pmnd.rs/). Раздел входит и в путь файла,
и в публичный import; плоские дубли и compatibility exports не создаются.
Grid принадлежит `gizmos`. Новые разделы появляются вместе с реальными
компонентами. Классификация не меняет общий Document, мировую ось Z-up и мм.

```text
space/
├── abstraction/   # Asset, Group, Text, Animation
├── gizmo/         # Grid
├── shader/        # Material
├── shape/         # Mesh, Line, LineSegments, Geometry
├── staging/        # Light
├── src/
└── tests/
```

`XRObjectElement` владеет полным семантическим преобразованием. Geometry,
Material, Object и Animation могут задать типизированную фабрику проекции;
Browser вызывает её для конкретной версии элемента и удерживает один
производный объект Engine.

`Grid` объявляет опорную сетку в плоскости XY через один `LineSegments`.
Параметры сетки и её преобразование задаются props; фабрикой производной
геометрии владеет Space. Повторный render и перемещение не пересоздают сетку,
пока её размер, число делений и цвета не изменились.

### Devtools

`devtool/inspector.ts` содержит публичный `createDomInspector`, `types.ts` —
его договор данных, а `tests/` — проверки поведения. Пакет читает существующий
Document: постоянные диагностические идентификаторы, снимки дерева и состояния,
изменения, размеры, области попадания и записи рисования. Renderer остаётся
необязательным источником данных; Experience может предоставить `readFrame(node)`.

Devtools не создаёт Document, Canvas, Renderer или цикл кадров, не содержит UI,
сетевого транспорта или доступа к GPU. Подписки создаются только явным вызовом
`createDomInspector` и освобождаются через `dispose`. Будущие инструменты отладки
развиваются в этом пакете по отдельным требованиям.

## Проверки

Проверки одного пакета находятся в `<package>/tests/`. Общие проверки находятся
в корневом `/tests/`:

```text
tests/
├── architecture/
├── experience/
└── acceptance/
```

Проверки являются требованиями к архитектуре. `todo` не считается выполненным
требованием.

Общий `check` сохраняет параллельность typecheck и tests. Типизация вложенных
пакетов выполняется последовательно: каждый TypeScript program самостоятельно
раскрывает зависимости, поэтому одновременный запуск всего дерева UI многократно
дублирует работу и перегружает машину. Package tests
выполняются последовательно, с собственным параллельным Bun runner внутри
каждого пакета: двойная параллельность всех пакетов и всех их тестов не
должна исчерпывать CPU и давать ложные timeout тяжёлых behavioral fixtures.
Assertions и deadlines от этого не меняются.

## Приёмка

Состав пакетов, публичные экспорты и зависимости проверяются обычными
архитектурными тестами. Поведение компонентов проверяют тесты владельцев
через публичные DOM и TSX API.

## Запрещено

- создавать второй `Document`, Canvas, Space или главный граф;
- добавлять обходы в UI и Node вместо исправления платформы;
- считать одни зелёные тесты полной приёмкой;
- выполнять push без отдельного указания.


### node-composition

Пакет `@zavx0z/immersive-nodes-node` содержит конкретные DiagramNode, ParameterNode и ContentNode.
ParameterNode использует Pane и готовые параметры. ContentNode составляет его
с произвольным содержимым: обе части сворачиваются независимо, сохраняя Stores,
элементы сокетов и подключения. Квадрат содержимого имеет сторону, равную ширине
ноды. DiagramNode показывает описание в прямоугольной, овальной или круглой Pane.
Прежние универсальные Node/NodeProps/NodeComponent и image-only NodePreview
заменены этими конкретными компонентами; отдельной базовой визуальной ноды нет.

Расчёт размеров использует существующий числовой договор; состояния входят во
вход layout callback. Переход не объявляет реализованным общий вывод геометрии
произвольного TSX/CSS и не меняет владельцев этой будущей возможности.


Markdown распознаёт fenced Mermaid flowchart и загружает официальный parser
по требованию. Владелец композиции — `@zavx0z/immersive-markdown`; он использует DiagramNode,
Link и Layout, не создавая отдельный Canvas/Document и не преобразуя диаграмму
в SVG-картинку. Mermaid-поддержка не переносится в UI.


### Общий просмотр графа

`graph-view-composition`: визуальные NodeTree/NodeEditor заменены на
GraphView/GraphEditor в `nodes/view/index.tsx` и `nodes/editor/index.tsx`.
Модель @zavx0z/immersive-nodes-tree остаётся прежней. GraphEditor использует общий GraphView;
Mermaid использует тот же просмотр без редакторского набора нод.
Готовые числовые планы сохранены как публичный вход scene. Новый input/layout
и GraphEditor.measureLayout используют реальные CSS-размеры и локальные anchors
до первого видимого кадра: [договор и проверки](nodes/measurement-gap.md).
TopDown получил отдельный contour-вход с совместимым flat Dagre order,
пересечениями фигур и rounded routes. [Числовые эталоны и границы parity](nodes/layout/top-down-parity.md)
отделяют upstream geometry от визуального принятия Desktop; точный Socket-вход сохраняется.
